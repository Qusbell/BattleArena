# 연결표 — 저장 테이블별 코드 연결 위치와 실행 시점

경로는 프로젝트 루트 기준입니다. 기록 담당 클래스는 `Source/ShootingArena/Private/Analyzer/ArenaMatchLogSubsystem.cpp`(월드 서브시스템, 이하 `MatchLog`)이며, 서버·단독 실행에서만 만들어집니다. 이벤트 순서와 발생 시각은 `MatchLog::AllocateEvent`가 부여합니다. 0초는 경기 규칙 액터(`AMatchRulesInfo`)가 경기 시작을 알리는 순간이며 `MatchLog::TryAnchorClock`이 맞춥니다. 저장은 `MatchLog::Flush`가 0.25초 주기로 한 트랜잭션에 모아서 하고, 실패 시 재시도·보관·종료 후 검증(`MaybeValidate`)을 합니다.

## 1. 경기·참가자

| 테이블 | 실행 시점 | 연결 위치 |
|---|---|---|
| `event` | 모든 이벤트 생성 시 | `MatchLog::AllocateEvent` (경기마다 1부터 증가) |
| `match` | 첫 캐릭터가 스폰되어 경기가 시작될 때 | `MatchLog::EnsureMatchStarted`. 제한 시간·목표 킬은 `AMatchRulesInfo`(로비 적용값), 없으면 GameState의 `GameConfig`. `StartAtKst`는 이 시점의 한국 표준시(UTC+9)를 `yy.MM.dd_HH:mm`(예: `26.10.31_16:32`)로 기록 |
| `match_end` | 게임의 종료 신호가 켜질 때, 또는 월드가 닫힐 때(`Forced`) | `MatchLog::Tick`(종료 감지) → `MatchLog::EndMatch`. 종료 신호는 GameState/GameMode의 `bIsMatchEnded` |
| `participant` | 참가자의 첫 스폰이 확정될 때 | `MatchLog::TryWriteParticipant`. 참가자 ID는 분석기의 컨트롤러 ID(`UArenaAnalyzeSubsystem::RegisterController`) |
| `participant_result` | 경기 종료 시 | `MatchLog::EndMatch`가 PlayerState의 `KillCount`/`DeathCount`를 읽음 (UI 문자열 아님) |
| `bot_settings` | 봇 참가자 기록 시 | `MatchLog::TryWriteParticipant`가 AI 컨트롤러의 `GetCharacteristic` 반환 구조체에서 9개 값을 읽어 해시(`B…`)로 저장 |
| `balance_settings` | 경기 시작 시 | `MatchLog::ArchiveBalanceSettings`. `/Game/QuakeLike_1_0/Data/Item` 아래 모든 DataTable 행을 JSON으로 보존하고 그 내용의 해시를 `SettingsVersion`으로 사용 |

## 2. 스폰·무기 상태

| 테이블 | 실행 시점 | 연결 위치 |
|---|---|---|
| `spawn`, `spawn_weapon` | 초기 무기 지급이 끝난 직후 | `UInitialWeaponLoadoutComponent::GrantLoadout`(`Source/ShootingArena/Private/Weapon/InitialWeaponLoadoutComponent.cpp`)의 끝 → `MatchLog::CompleteSpawn`. 스폰 회차는 `TrackId + 1`(`UArenaAnalyzeSubsystem::SetTrackedPawn` → `MatchLog::NoteLifeBegin`) |
| `spawn_end` | 사망 / 새 캐릭터 소유 / 경기 종료 | `MatchLog::EndLife` (사유 `Death`, `Leave`, `MatchEnd`). 같은 생애는 한 번만 종료 |
| `weapon_equip` | 무기 교체가 확정될 때 | **블루프린트** `Content/QuakeLike_1_0/Inventory/BPC_Inventory` 이벤트 그래프, `Swap` 커스텀 이벤트의 Sequence `then_2` → `Record Weapon Swap` → `MatchLog::RecordWeaponSwap` |

## 3. 발사·피해·사망

| 테이블 | 실행 시점 | 연결 위치 |
|---|---|---|
| `fire` | 실제 발사가 성립한 지점 | `UArenaCombatLibrary::BeginWeaponShot`(무기 블루프린트가 호출) → `UArenaAnalyzeSubsystem::RecordShot` → `MatchLog::RecordFire`. 공격 ID = 분석기의 `ShotId`. 한 발사의 펠릿 수는 `RecordTraces`(`ArenaCombatLibrary.cpp`)에서 갱신 |
| `damage` | `ApplyDamage` 전후. `InputDamage`는 `BPC_Life`가 `Record Damage Input` 노드로 알려 줌 | `UArenaAnalyzeSubsystem::ApplyShotDamage`가 `MatchLog::BeginDamage`(이벤트 예약) → 엔진 `ApplyDamage` → `MatchLog::EndDamage`. 적용 전후 체력·아머는 피해자의 `BPC_Life.LifeInfo`에서 읽음. 공격자 버프는 `BPC_Buff`의 `currentBuffTag` |
| `death` | 사망 확정 | `UArenaCombatLibrary::ConfirmDeath`(`BPC_Life`가 호출) → `UArenaAnalyzeSubsystem::RecordDeath` → `MatchLog::RecordDeath`. 직접 원인은 같은 호출 안의 피해 이벤트(`CauseEventSequence`) |
| 처치 인정 갱신 | 게임의 처치 판정 완료 | `URecentAttackerComponent::ResolveDeathCredit`(`Source/ShootingArena/Private/Combat/RecentAttackerComponent.cpp`) → `RecordCredit` → `MatchLog::RecordCredit`. 사망 행이 먼저 있으면 `UPDATE`, 나중이면 보관했다가 사망 시 반영 |

## 4. 아이템·버프

| 테이블 | 실행 시점 | 연결 위치 |
|---|---|---|
| `item_spawn` | 아이템 액터 `BeginPlay` | **블루프린트** `Content/QuakeLike_1_0/DropItem/BP_DropItem`, `Event BeginPlay`와 `Setup Mesh` 사이 → `Record Drop Item Spawned`. 분류·행 이름·사유는 `MatchLog::DescribeDropItem`이 아이템에서 읽음. 사망 드롭은 소유자가 `ADeathDropCarrier`인 것으로 판별 |
| `pickup` | 획득 효과가 적용되기 직전에 상태 캡처, 효과 성공 후 기록 | `BP_DropItem` 이벤트 그래프. `Apply Item Effect` 직전 `Begin Item Pickup`, 성공 분기 직후 `Commit Item Pickup` → `MatchLog::BeginItemPickup`/`CommitItemPickup`. 체력 아이템의 실제 증가량은 획득 전후 차이 |
| `item_remove` | 아이템 액터 파괴 | `MatchLog::HandleItemDestroyed`(`OnDestroyed` 델리게이트). 획득 기록이 있으면 `PickedUp`, 없으면 `Despawned`, 경기 종료 시 남은 것은 `MatchEnd`. 블루프린트 수정 없음 |
| `buff` (획득·갱신·교체) | 버프 적용 직후 | **블루프린트** `Content/QuakeLike_1_0/Buff/BPC_Buff`의 `ApplyBuff`와 `ApplyDroppedBuff`, `Set Buff Presentation` 뒤 → `Record Buff Applied`. 종료 예정 시각은 컴포넌트의 `buffEndServerTime`에서 계산(기본 지속 시간 재계산 없음) |
| `buff` (만료) | 타이머 종료 | `BPC_Buff` 이벤트 그래프, `OnBuffTimerFinished`의 `Multicast Set Buff Overlay` 뒤 → `Record Buff Expired` |
| `buff` (사망으로 소실) | 사망 확정 | `MatchLog::RecordDeath`가 사망 이벤트를 원인으로 `Expire`를 남김 (블루프린트 수정 없음) |

## 5. 블루프린트 수정 목록 (4개 에셋)

| 에셋 | 추가한 노드 |
|---|---|
| `DropItem/BP_DropItem` | `Record Drop Item Spawned`(BeginPlay), `Begin Item Pickup`, `Commit Item Pickup`(겹침 이벤트) |
| `Inventory/BPC_Inventory` | `Record Weapon Swap`(`Swap` 이벤트) |
| `Life/BPC_Life` | `Record Damage Input`(`OwnerTakeDamage`의 `Branch(then)`과 `Is Valid` 사이. `Victim` ← `Get Owner`, `InputDamage` ← `Get Buff Take Damage`의 Final Damage) |
| `Buff/BPC_Buff` | `Record Buff Applied`(`ApplyBuff`, `ApplyDroppedBuff`), `Record Buff Expired`(`OnBuffTimerFinished`) |

이 노드들은 `UArenaMatchLogLibrary`(`Source/ShootingArena/Public/Analyzer/ArenaMatchLogLibrary.h`)의 **Arena Match Log** 카테고리에 있고, 경기 중이 아닐 때는 아무것도 하지 않습니다.
