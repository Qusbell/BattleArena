# 큰 오차 네 사례의 원인 조사

측정일: 2026-10-21. 대상: 사용자가 BP_PathLink27 배치를 조정하고 Build한 현재 Lvl_PortalMap.

네 사례의 큰 차이는 BP_PathLink27 자체의 거리 오류보다 **기존 상세 Route 탐색이 더 짧은 Link 조합을 놓치는 후보 선택 정책**에서 발생했습니다. 상세 경로는 선택한 일반 이동 구간을 정밀하게 계산하지만, 전체 Link 조합의 최단 경로를 보장하지 않습니다.

## 같은 좌표로 비교한 결과

단위는 m입니다. 마지막 열은 추정값을 전체 Link 그래프의 정밀 최단 거리와 비교한 값입니다.

| 사례 | 기본 상세 Route | 전체 그래프 정밀 거리 | 현재 추정 | 전체 그래프의 Link | 추정 상대 오차 |
|---:|---:|---:|---:|---|---:|
| 31 | 123.813 | 106.023 | 104.667 | BP_PathLink28 | -1.279% |
| 74 | 110.728 | 96.681 | 95.296 | BP_PathLink28 | -1.433% |
| 141 | 139.606 | 124.712 | 123.263 | BP_PathLink28 | -1.162% |
| 181 | 110.201 | 84.414 | 84.090 | BP_PathLink11 | -0.384% |

따라서 기존 보고서의 10% 초과 과소평가 네 개는, 이 사례들에서는 더 긴 경로를 선택한 상세 API를 기준으로 비교한 수치였습니다. 추정 오차가 완전히 없다는 뜻은 아니며, 이번에 전체 그래프와 대조한 범위는 이 네 쌍입니다.

## 31·74·141번: 가까운 Link 후보 제한

기본 설정은 시작·도착 각각 직선거리 기준 가까운 Link 6개부터 검사합니다. 실제로 더 짧은 경로를 만드는 Link28은 세 사례 모두 시작점에서 10번째입니다. 141번에서는 목표점에서도 8번째입니다.

기본 상세 경로는 Link12 → Link8 → Link27 → Link28을 선택했습니다. 후보 수만 6에서 32로 늘리면 세 사례 모두 Link28만 사용하는 더 짧은 경로를 선택했고, 독립적인 전체 그래프 정밀 계산과 일치했습니다.

후보 확장은 선택된 경로의 끝 구간이 실패하거나 예상보다 지나치게 길 때 동작합니다. 현재 선택 경로가 유효하다는 사실만으로는 제외된 후보가 더 짧지 않다는 것을 증명할 수 없습니다.

## 181번: 장애물 배수가 더 좋은 후보를 가림

181번은 후보를 전부 열어도 기존 장애물 배수 1.5에서는 Link27 경로 110.201m를 유지했습니다. Link11의 시작·끝 연결 구간은 LineTrace가 모두 막혔고, 정밀 검사 전 임시 비용은 다음과 같았습니다.

| 구간 | 직선거리 × 1.5 | 실제 NavMesh 거리 |
|---|---:|---:|
| 시작점 → Link11 진입점 | 53.946 | 40.517 |
| Link11 도착점 → 목표점 | 43.152 | 29.203 |
| Link11 자체 | 14.694 | 14.694 |
| 합계 | 111.793 | 84.414 |

임시 비용 111.793m가 이미 검증한 Link27 경로 110.201m보다 길어 보이므로 Link11은 선택되지 않습니다. 선택된 경로의 끝 구간만 정밀 검사하는 구조라 Link11의 실제 비용을 확인하지 않고 종료합니다.

모든 후보를 연 상태에서 배수만 1.5에서 1로 바꾸자 상세 API도 84.414m를 반환했습니다. 원래 후보 수 6에서도 배수를 1로 바꾸면 이번 네 사례는 모두 전체 그래프 결과와 일치했습니다. 후보 제한과 임시 비용, 확장·종료 조건이 함께 작용하므로 후보 개수만을 유일한 원인으로 볼 수는 없습니다.

직선거리의 1.5배는 실제 경로 거리의 하한이 아닙니다. 검증하지 않은 경로를 이 값으로 비싸게 평가하고 탐색을 종료하면 더 짧은 경로를 놓칠 수 있습니다.

## 검증 방법과 배치 확인

- 활성·사용 가능 Link 10개에서 방향별 Traversal 12개를 구성했습니다.
- 모든 시작·끝 연결과 Link 사이 일반 이동을 동기 NavMesh로 정밀 조회하고, 전체 그래프 Dijkstra를 별도로 수행했습니다. 유효하지 않거나 부분 경로인 결과는 제외했습니다.
- 기존 상세 Route의 일반 이동 구간은 독립 조회값과 차이가 0cm였습니다. 텔레포트 및 Link 자체 비용도 기존 정의를 사용했습니다.
- 네이티브 NavLink Actor·Component는 없었습니다. 숨은 네이티브 Link를 통한 우회가 이번 결과를 만든 것은 아닙니다.
- 후보 수와 장애물 배수를 개별 변경하는 대조 실험으로 원인을 확인했습니다. 진단 스크립트는 finally에서 원래 설정을 복구합니다.

현재 Link27 진입점은 (410, -2439, 1155.129)cm, 도착점은 (734, -2222, 691)cm이며, 자체 비용은 6.062m입니다. 캐시 검증은 통과했고 상세 Route에 새 좌표와 비용이 반영됐습니다. 기존 200쌍도 상세·추정 모두 성공했습니다. 첫 세 쌍의 최종 목표는 시작점보다 높으므로 네 사례가 모두 XY가 비슷한 하향 이동이라는 공통점도 없습니다.

운영 설정은 후보 수 6, 장애물 배수 1.5, 방향 보정 강도 1, 직선 혼합 강도 0으로 복구했습니다. 이번 조사는 런타임 구현, Link 배치, Bake를 변경하지 않았고 사용자 맵의 미저장 상태를 유지했습니다. 실제 AI 낙하 물리 검증은 포함하지 않습니다.

## 이후 수정 방향

모든 후보에 정밀 조회를 강제하면 비용이 늘어납니다. 최소 변경 방향은 미검증 후보에는 직선거리처럼 하한이 되는 비용을 사용하고, 장애물 배수는 검사 우선순위에만 사용하는 것입니다. 미검증 경로의 하한이 현재 최선보다 짧을 가능성이 남아 있다면 검사 또는 후보 확장을 계속해야 합니다. 제외된 후보도 하한으로 걸러내는 방식이 필요합니다. 이는 후속 구현 제안이며 이번 조사에서는 적용하지 않았습니다.
