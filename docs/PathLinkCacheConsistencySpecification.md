# Path Link 거리 캐시 정합성 작업 명세

## 목적

사용 중인 맵에서 Path Link 거리 캐시가 에디터, PIE 및 패키징 게임의 Static NavMesh와 일관되게 동작하도록 합니다. 기존 에디터 사전 베이크와 맵 내 저장 방식은 유지하며, 사용할 수 있는 캐시가 없을 때는 서버에서 재생성하고 이후 실행에서도 재사용할 수 있도록 합니다.

## 확인된 문제

`Lvl_PortalMap`에서 에디터 NavMesh에는 현재 NavMesh Bounds 밖에 남아 있는 타일 12개가 포함되어 있었습니다. 에디터 사전 베이크는 총 225개 타일과 지면 폴리곤 2,074개를 기준으로 했지만, PIE 복제 시 Bounds 밖 타일이 제외되어 213개 타일과 지면 폴리곤 2,041개가 남았습니다. 공통된 213개 타일의 내부 데이터와 NavMesh 설정 해시는 일치했습니다.

현재는 PIE 시작 전 에디터 월드에서 캐시가 유효하다고 판단해도, 이후 PIE 월드에서 NavMesh가 달라지면 캐시 전체를 사용할 수 없게 됩니다. `GetEstimatedRouteDistance`는 이때 `false`를 반환하며, 런타임에서 캐시를 재생성하지 않습니다. Bounds 밖 타일이 남은 최초 원인과 시점은 확인되지 않았습니다.

## 적용 범위

- Static NavMesh와 플레이 중 변경되지 않는 Path Link를 지원합니다.
- 동적 NavMesh 변경 및 런타임 스트리밍으로 인한 데이터 변경 대응은 후속 과제로 남깁니다.
- 기존의 에디터 사전 베이크와 맵 내 캐시 저장 기능을 유지합니다.
- 런타임 재생성과 별도 파일을 통한 실행 간 재사용을 추가합니다.
- AI의 목표 선정 로직이나 재생성 완료 후 목표 재선정을 별도로 보장하는 동작은 이번 범위에 포함하지 않습니다.

## 사전 베이크 정합성

에디터에서 사전 베이크할 때 실제 저장·실행될 NavMesh와 다른 타일이 포함되어 캐시가 거부되는 문제를 수정합니다. 특히 현재 문제처럼 Bounds 밖에 남은 타일이 에디터와 PIE 간 불일치를 일으키지 않아야 합니다.

검증 해시에서 타일을 제외하는 것만으로 처리하지 않습니다. 폴리곤의 목록과 인덱스, 연결 정보, 거리표 및 실제 거리 계산에 사용되는 NavMesh가 동일한 실행 대상과 일치해야 합니다. Bounds 경계에 걸친 타일 및 레벨별 소유 관계는 엔진의 실제 저장·실행 규칙을 고려합니다. 구체적인 구현 방식은 엔진 동작을 확인하고 검증 가능한 방식으로 결정합니다.

## 런타임 캐시 재생성

1. 서버 월드 시작 시 기존 캐시를 가능한 한 이르게 검증합니다.
2. 유효한 맵 내 사전 베이크를 우선 사용합니다. 이것이 없거나 유효하지 않으면 이전 실행에서 저장한 런타임 캐시를 확인합니다.
3. 사용할 수 있는 캐시가 없으면 NavMesh가 준비될 때까지 주기적으로 확인하고, 준비되면 서버에서 재생성합니다.
4. 여러 봇의 요청이 겹쳐도 서버 월드당 재생성 작업 하나를 공유합니다.
5. 재생성 작업은 여러 프레임에 나눕니다. 기본 예산은 프레임당 2ms이며 설정할 수 있습니다. 단일 NavMesh 경로 탐색 자체가 예산을 초과하는 경우는 허용합니다.
6. 재생성이 완료되기 전의 거리 추정 요청은 `false`를 반환합니다. 완료 후의 요청부터 새 캐시를 사용합니다.
7. 이번 작업에서는 런타임 재생성의 메모리·작업량 상한을 두지 않습니다. 큰 맵에서 생성 시간과 메모리 사용량이 크게 증가할 수 있습니다.

NavMesh 준비 대기와 실제 생성 오류를 구분합니다. 생성 중 상태와 실패 원인을 확인할 수 있도록 노출하고 로그를 남깁니다. 실제 생성 오류는 무한 재시도하지 않고 실패 상태와 원인을 유지합니다.

## 런타임 결과의 저장과 재사용

- 런타임에서 완성한 캐시는 서버의 쓰기 가능한 `Saved` 디렉터리 아래 맵별 파일로 보관합니다. 기존 맵 파일이나 맵 내 사전 베이크를 덮어쓰지 않습니다.
- 다음 실행에서는 파일의 버전, 맵, 현재 NavMesh 및 Path Link 정합성을 검증한 뒤에만 사용합니다. 파일 손상이나 불일치가 있으면 사용하지 않고 새로 생성합니다.
- 유효한 맵 내 사전 베이크가 있으면 이를 우선 사용합니다.
- PIE용 파일은 패키징 게임의 파일과 분리하며, 이후 PIE 실행에서 검증 후 재사용합니다.
- 파일 저장에 실패해도 현재 실행에서 완성된 메모리 캐시는 계속 사용하고, 저장 실패를 상태와 로그에서 확인할 수 있게 합니다.

## 검증 및 완료 기준

- 코드 빌드와 관련 자동화 테스트를 수행합니다.
- 현재 맵에서 Bounds 밖 타일에 의해 발생한 에디터와 PIE 간 불일치가 해결되고, 거리 추정이 정상 동작하는지 확인합니다.
- 사전 베이크가 유효할 때 이를 사용하고, 없는 경우 또는 검증 실패 시 런타임 재생성이 시작되는지 확인합니다.
- NavMesh 준비 대기, 생성 중 `false`, 완료 후 결과 사용 및 상태·오류 보고를 검증합니다.
- 여러 요청이 하나의 월드별 생성 작업을 공유하고, 프레임 예산에 따라 작업이 분산되는지 확인합니다. 단일 경로 탐색의 예산 초과는 구분해 평가합니다.
- 런타임 파일의 저장, 다음 실행에서의 검증 및 재사용, 손상·버전 불일치·데이터 불일치 시 재생성, 저장 실패 시 메모리 캐시 사용을 검증합니다.
- 기존 에디터 사전 베이크와 맵 저장 기능 및 양방향 Path Link의 거리 계산이 유지되는지 확인합니다.
- 이 컴퓨터에서는 실제 패키징이 불가능하므로, 패키징된 게임의 실행 검증은 Git 빌드 엔진이 있는 다른 컴퓨터에서 별도 확인할 항목으로 남깁니다. PIE 및 자동화 테스트 결과를 패키징 실행 검증으로 간주하지 않습니다.
